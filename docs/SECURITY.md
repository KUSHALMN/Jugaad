## 🛡️ Security Architecture

### 1. Cryptographic Token Verification & Zero-Trust Headers
- All client requests must supply a verified Bearer token (Firebase ID token for Flutter mobile clients, or Supabase Auth JWT for the React Admin Operations Console).
- Unsigned or spoofed identity headers (such as `X-Admin-Id`) are strictly rejected. Admin privileges are verified by inspecting the cryptographically decoded user identity in the database (`users.role = 'admin'`).

### 2. Dual-Layer Dispatch Authorization & Concurrency Locks
- Workers can only accept or reject jobs on their own behalf. The caller's authenticated identity is verified against `body.worker_id` before dispatch handling.
- Double-accept race conditions are prevented using atomic database conditional updates (`UPDATE jobs ... WHERE status IN ('open', 'searching') RETURNING id`) and Redis distributed locks.

### 3. Private Government ID Storage & Signed URLs
- The `worker-verification` bucket storing sensitive Aadhaar cards and driver's licenses is strictly private.
- Public URLs (`getPublicUrl`) are disabled for verification buckets. Identity documents are accessed exclusively through short-lived (15-minute TTL) cryptographic signed URLs generated by the backend for authenticated administrators.

### 4. OTP Rate Limiting & Production Hardening
- Authentication OTP generation and validation are rate-limited via Redis with automatic lockout after consecutive failed attempts.
- Development fallback codes (`123456`, `000000`) are strictly restricted to local debug mode (`ENV=local` and `DEBUG=true`) and rejected in staging and production.

### 5. Escrow Payment State Integrity
- Razorpay webhook signatures (`X-Razorpay-Signature`) and checkout callback signatures are cryptographically validated using HMAC-SHA256.
- Upfront booking payments are held securely in an `escrowed` state, and settlements are strictly gated until job completion with no pending price adjustments.
